Face Animator

Animate face visibility on standard prims, linked objects and mesh directly inside Second Life.

How it worksQuick reference
STANDARD PRIMSMESHPENDULUMLINEARRANDOM

One system. Multiple uses.

  • Animate existing faces on standard prims.
  • Control multiple linked parts independently.
  • Animate existing mesh texture faces.
  • Use prepared mesh states for apparent geometry animation.
01

What objects can it animate?

Face Animator works with the numbered faces of Second Life prims.

It is not limited to mesh.

Standard prims can use their normal existing faces directly as animation states. This was verified in Second Life with three linked standard box prims.

Direct use

  • Boxes, cylinders, prisms and other standard prims.
  • Multiple linked standard prims.
  • Mesh whose existing texture faces are the states you want to alternate.
  • Mixed linksets containing standard prims and mesh.

Specially prepared mesh

Only required when different pre-built geometry shapes must act as animation frames. Each shape must belong to a separate material / texture face.

What it does not do

Face Animator does not move vertices or deform objects. It shows and hides the configured FACES.

The current version controls legacy / Blinn-Phong alpha. Faces using PBR materials are not supported by this visibility method.

02

Installation

Keep the script and notecard together.

  1. Rez or edit the compatible object.
  2. Open the prim where Face Animator will be installed. The root prim is recommended.
  3. Place the supplied script and the notecard named exactly Config Face Animator in that same prim inventory.
  4. Edit the notecard using the real linked-prim names.
  5. Save it and wait for loading to finish.
  6. Check owner chat for a valid-configuration message.
Same prim inventory

Config Face Animator must be in the inventory of the same prim that contains the script.

03

Config Face Animator

Block-based configuration, one PART after another.

Lines starting with # are comments and empty lines are ignored.

PART=COINS
MODE=PENDULUM
FACES=0,1,2,3,4
START=0
DELAYS=400,300,200,300,400
REPEAT=2
REPEAT_DELAY=300

To add another animated prim, start another block with a new PART=... line.

Large notecards

The script reads the complete notecard until EOF. The real stress test read 510 lines and stored 64 PARTs successfully. Large configurations can take noticeably longer to finish loading.

04

MODE

Choose how each PART advances through its states.

PENDULUM

MODE=PENDULUM

Moves to one end and then reverses direction.

0 → 1 → 2 → 3 → 4 → 3 → 2 → 1 → 0

LINEAR

MODE=LINEAR

Moves to the last state and loops directly back to the first.

0 → 1 → 2 → 3 → 4 → 0

RANDOM

MODE=RANDOM

Jumps randomly among configured FACES without immediately repeating the current face.

05

FACES and START

Define exactly which faces form the animation.

FACES=0,1,2,3,4
START=2
  • FACES accepts 2 to 8 indices.
  • They do not need to be consecutive.
  • START must appear inside FACES.
  • A face not listed in FACES is never intentionally modified by Face Animator.
When changing an existing configuration

If a face was hidden by an older configuration and you later remove it from FACES, Face Animator stops controlling it. Restore its alpha manually or use a clean copy before testing the new configuration.

06

DELAYS

Visible time for each state, in milliseconds.

FACES=0,1,2,3,4
DELAYS=400,300,200,300,400

Each value belongs to the FACE in the same position. Allowed range: 100..60000 ms.

FACES and DELAYS must contain exactly the same number of values.

07

REPEAT and REPEAT_DELAY

Optional control of complete cycles for each PART.

SettingResult
REPEAT missingTraditional continuous animation.
REPEAT=Traditional continuous animation. REPEAT_DELAY is ignored.
REPEAT=2Two complete cycles, then stop on START.
REPEAT=INFINITEControlled complete cycles forever.
REPEAT=3
REPEAT_DELAY=2000

REPEAT_DELAY is in milliseconds and only applies when REPEAT is active. If missing, empty or 0, START keeps its normal DELAYS value between cycles.

Numeric REPEAT range: 1..1000000. REPEAT_DELAY range: 0..86400000 ms.

08

Multiple PARTs and capacity

Each linked prim can use its own mode, START and timing.

PART=SKIRT_LEFT
MODE=LINEAR
FACES=0,1,2,3,4
START=0
DELAYS=200,150,100,150,200

PART=SKIRT_RIGHT
MODE=RANDOM
FACES=0,1,2,3,4
START=2
DELAYS=400,300,200,300,400
64maximum logical PART entries
8maximum FACES per PART
Verified capacity

Face Animator v1.6.2 was tested in Second Life with 64 PARTs × 5 FACES = 320 frames. The theoretical 64 × 8 = 512-frame combination has not been tested and is not guaranteed. Actual capacity also depends on available script memory.

09

Standard prims and advanced mesh

The same engine supports simple face effects and apparent geometry animation.

Standard prims

No Blender preparation is required. Use their existing numbered faces directly in FACES.

Regular mesh

Existing texture faces can be used directly when those faces are the states you want to alternate.

Mesh with geometry states

If each face should represent a different shape, prepare the mesh in advance:

geometry state
→ mesh material
→ Second Life texture face
→ number used in FACES

Face Animator does not create those shapes. It only switches their visibility.

10

Troubleshooting

Quick checks before editing the script.

Nothing animates

Confirm the mesh was prepared with separate texture faces, PART exactly matches the prim name, and FACES uses indices that really exist.

A PBR face does not disappear

The current method uses Blinn-Phong alpha. PBR material faces do not visually respond to this visibility method.

The script says PART does not exist

PART uses the exact prim name. Check spaces, punctuation, case and the real name reported by the startup scan.

Configuration takes a long time

Notecards are read line by line. Hundreds of lines can take noticeable time. Wait for the EOF/valid configuration message.

Configuration rejected because of memory

Reduce the total number of PARTs or FACES. The 64-PART limit is logical, but Mono script memory is still finite.

An old face remains invisible after changing FACES

Restore its alpha manually or use a clean copy. A face removed from FACES is intentionally no longer controlled.
