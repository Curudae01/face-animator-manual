Face Animator

Animação visual para meshes preparados com vários estados geométricos distribuídos entre texture faces.

Verificar compatibilidadeReferência rápida
PENDULUMLINEARRANDOMAté 64 PARTs

Antes de começar

  • O mesh deve ser preparado especificamente para este sistema.
  • Cada estado visual deve usar uma texture face diferente.
  • Máximo de 8 texture faces por mesh prim.
  • Faces PBR não são compatíveis com o método atual de visibilidade.
01

O meu mesh é compatível?

Verifique isto antes de instalar o script.

Face Animator não anima qualquer mesh.

O objeto deve conter previamente vários estados geométricos no mesmo mesh prim, atribuídos a materiais / texture faces separados.

Compatível

  • Roupa, acessórios ou efeitos criados com estados separados.
  • 2 a 8 FACES configuradas por PART.
  • Faces legacy / Blinn-Phong para visibilidade por alpha.
  • Prims ligados com nomes únicos.

Não compatível

  • Mesh normal com uma única geometria esperando deformação pelo script.
  • Animação por ossos, rigging ou keyframes do Blender.
  • Faces PBR que devam desaparecer com este método.
  • Dois prims configurados com o mesmo nome.

Second Life suporta até 8 texture faces por mesh prim. O limite é por prim, não pelo linkset completo.

02

Instalação

Mantenha o script e a notecard juntos.

  1. Rezz ou edite o objeto compatível.
  2. Abra o prim onde Face Animator será instalado. Recomendamos o root prim.
  3. Coloque no mesmo inventário o script fornecido e a notecard chamada exatamente Config Face Animator.
  4. Edite a notecard com os nomes reais dos prims ligados.
  5. Guarde e espere a leitura terminar.
  6. Confirme no chat do proprietário que a configuração foi aceite.
Mesmo prim

Config Face Animator deve estar no inventário do mesmo prim que contém o script.

03

Config Face Animator

Configuração por blocos, uma PART depois da outra.

Linhas iniciadas por # são comentários; linhas vazias são ignoradas.

PART=COINS
MODE=PENDULUM
FACES=0,1,2,3,4
START=0
DELAYS=400,300,200,300,400
REPEAT=2
REPEAT_DELAY=300

Para outro prim animado, comece um novo bloco com PART=....

Notecards longas

O script lê a notecard inteira até EOF. O teste real leu 510 linhas e guardou 64 PARTs corretamente. Configurações grandes podem demorar mais para carregar.

04

MODE

Escolha como cada PART percorre os estados.

PENDULUM

MODE=PENDULUM

Vai até uma extremidade e regressa.

0 → 1 → 2 → 3 → 4 → 3 → 2 → 1 → 0

LINEAR

MODE=LINEAR

Vai até ao último estado e regressa diretamente ao primeiro.

0 → 1 → 2 → 3 → 4 → 0

RANDOM

MODE=RANDOM

Salta aleatoriamente entre FACES configuradas sem repetir imediatamente a face atual.

05

FACES e START

Defina exatamente as faces da animação.

FACES=0,1,2,3,4
START=2
  • FACES aceita 2 a 8 índices.
  • Não precisam ser consecutivos.
  • START deve existir dentro de FACES.
  • Uma face fora de FACES não é modificada intencionalmente.
Ao alterar uma configuração existente

Se uma face foi ocultada por uma configuração anterior e depois removida de FACES, restaure o alpha manualmente ou use uma cópia limpa.

06

DELAYS

Tempo visível de cada estado, em milissegundos.

FACES=0,1,2,3,4
DELAYS=400,300,200,300,400

Cada valor corresponde à FACE na mesma posição. Intervalo: 100..60000 ms. FACES e DELAYS devem ter a mesma quantidade de valores.

07

REPEAT e REPEAT_DELAY

Controlo opcional de ciclos completos por PART.

ConfiguraçãoResultado
REPEAT ausenteAnimação contínua tradicional.
REPEAT=Animação contínua; REPEAT_DELAY é ignorado.
REPEAT=2Dois ciclos completos e paragem em START.
REPEAT=INFINITECiclos completos infinitos controlados.
REPEAT=3
REPEAT_DELAY=2000

REPEAT_DELAY só atua com REPEAT ativo. Se estiver ausente, vazio ou 0, usa-se o DELAYS normal de START entre ciclos. REPEAT: 1..1000000. REPEAT_DELAY: 0..86400000 ms.

08

Várias PARTs e capacidade

Cada prim ligado pode ter o seu próprio modo, START e tempos.

PART=SKIRT_LEFT
MODE=LINEAR
FACES=0,1,2,3,4
START=0
DELAYS=200,150,100,150,200

PART=SKIRT_RIGHT
MODE=RANDOM
FACES=0,1,2,3,4
START=2
DELAYS=400,300,200,300,400
64PARTs lógicas máximas
8FACES máximas por PART
Capacidade testada

v1.6.2 foi testado com 64 PARTs × 5 FACES = 320 frames. 64 × 8 = 512 frames não foi testado nem é garantido. A capacidade real também depende da memória disponível.

09

Como preparar o mesh

A geometria animada é criada antes de chegar ao Second Life.

estado geométrico
→ material do mesh
→ texture face do Second Life
→ número usado em FACES
  • Cada posição visual precisa do seu próprio material / texture face.
  • Geometria estática deve ficar numa face separada e fora de FACES.
  • Verifique os números reais das faces após o upload.
10

Problemas frequentes

Verificações rápidas antes de editar o script.

Nada anima

Confirme preparação por texture faces, nome PART exato e índices FACES existentes.

Uma face PBR não desaparece

O método atual usa alpha Blinn-Phong; faces PBR não respondem visualmente a este método.

PART não existe

Verifique o nome exato apresentado pelo scan inicial.

A configuração demora

A notecard é lida linha por linha. Espere pela mensagem EOF/configuração válida.

Configuração rejeitada por memória

Reduza o total de PARTs ou FACES.
