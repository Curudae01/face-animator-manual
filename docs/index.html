Face Animator

Animación visual para meshes preparados con varios estados geométricos distribuidos entre texture faces.

Comprobar compatibilidadReferencia rápida
PENDULUMLINEARRANDOMHasta 64 PART

Antes de empezar

  • El mesh debe estar preparado específicamente para este sistema.
  • Cada estado visual debe ocupar una texture face distinta.
  • Máximo 8 texture faces por prim mesh.
  • Las caras PBR no funcionan con el método actual de visibilidad.
01

¿Es compatible mi mesh?

Esta comprobación es obligatoria antes de instalar el script.

Face Animator no anima cualquier mesh.

El objeto debe haberse creado con varios estados geométricos ya presentes dentro del mismo prim mesh y asignados a materiales / texture faces separados.

Compatible

  • Ropa, accesorios o efectos creados expresamente con estados separados.
  • Entre 2 y 8 FACES configuradas por PART.
  • Caras legacy / Blinn-Phong para la visibilidad por alpha.
  • Prims enlazados con nombres únicos.

No compatible

  • Un mesh normal con una sola geometría esperando que el script la deforme.
  • Animación por huesos, rigging o keyframes de Blender.
  • Caras PBR si se espera que desaparezcan con este sistema.
  • Dos prims configurados con el mismo nombre.

Second Life admite hasta 8 texture faces por prim mesh. Ese límite se aplica a cada prim individual, no al linkset completo.

02

Instalación

Script y notecard deben permanecer juntos.

  1. Rezea o edita el objeto compatible.
  2. Abre el prim donde instalarás Face Animator. Recomendamos el root prim.
  3. Introduce en ese mismo inventario el script suministrado y la notecard llamada exactamente Config Face Animator.
  4. Edita la notecard con los nombres reales de los prims enlazados.
  5. Guarda y espera a que termine la lectura.
  6. Comprueba en el chat del propietario que la configuración ha sido aceptada.
Mismo prim

Config Face Animator debe estar en el inventario del mismo prim que contiene el script.

03

Config Face Animator

Una configuración por bloques, una PART detrás de otra.

Las líneas que empiezan por # son comentarios y las líneas vacías se ignoran.

PART=COINS
MODE=PENDULUM
FACES=0,1,2,3,4
START=0
DELAYS=400,300,200,300,400
REPEAT=2
REPEAT_DELAY=300

Para añadir otro prim animado, empieza otro bloque con una nueva línea PART=....

Notecards largas

El script lee la notecard completa hasta EOF. La prueba de estrés real leyó 510 líneas y almacenó 64 PART correctamente. Una configuración grande puede tardar bastante más en terminar de cargar.

04

MODE

Elige cómo avanza cada PART entre sus estados.

PENDULUM

MODE=PENDULUM

Avanza hasta un extremo y vuelve en sentido contrario.

0 → 1 → 2 → 3 → 4 → 3 → 2 → 1 → 0

LINEAR

MODE=LINEAR

Avanza hasta el último estado y vuelve directamente al primero.

0 → 1 → 2 → 3 → 4 → 0

RANDOM

MODE=RANDOM

Salta aleatoriamente entre las FACES configuradas sin repetir inmediatamente la cara actual.

05

FACES y START

Define exactamente qué caras forman la animación.

FACES=0,1,2,3,4
START=2
  • FACES admite entre 2 y 8 índices.
  • No es necesario que sean consecutivos.
  • START debe aparecer dentro de FACES.
  • Una cara que no aparece en FACES nunca debe ser modificada por Face Animator.
Al cambiar una configuración existente

Si una cara estaba oculta por una configuración anterior y después la eliminas de FACES, Face Animator dejará de tocarla. Restaura manualmente su alpha o utiliza una copia limpia del objeto antes de probar la nueva configuración.

06

DELAYS

Tiempo visible de cada estado, en milisegundos.

FACES=0,1,2,3,4
DELAYS=400,300,200,300,400

Cada valor corresponde a la FACE de la misma posición. Rango permitido: 100..60000 ms.

FACES y DELAYS deben contener exactamente la misma cantidad de valores.

07

REPEAT y REPEAT_DELAY

Control opcional de ciclos completos por PART.

ConfiguraciónResultado
REPEAT ausenteAnimación continua tradicional.
REPEAT=Animación continua tradicional. REPEAT_DELAY se ignora.
REPEAT=2Dos ciclos completos y parada en START.
REPEAT=INFINITECiclos completos infinitos controlados.
REPEAT=3
REPEAT_DELAY=2000

REPEAT_DELAY se expresa en milisegundos y solo actúa cuando REPEAT está activo. Si falta, está vacío o vale 0, se utiliza el DELAYS normal de START entre ciclos.

REPEAT numérico admite 1..1000000. REPEAT_DELAY admite 0..86400000 ms.

08

Varias PART y capacidad

Cada prim enlazado puede tener su propio modo, START y velocidad.

PART=SKIRT_LEFT
MODE=LINEAR
FACES=0,1,2,3,4
START=0
DELAYS=200,150,100,150,200

PART=SKIRT_RIGHT
MODE=RANDOM
FACES=0,1,2,3,4
START=2
DELAYS=400,300,200,300,400
64PART lógicas máximas
8FACES máximas por PART
Capacidad probada

Face Animator v1.6.2 fue probado en Second Life con 64 PART × 5 FACES = 320 frames. La combinación teórica 64 × 8 = 512 frames no ha sido probada y no se garantiza. La capacidad real también depende de la memoria disponible.

09

Cómo debe prepararse el mesh

La geometría animada se crea antes de llegar a Second Life.

Modelo mental:

estado geométrico
→ material del mesh
→ texture face de Second Life
→ número utilizado en FACES
  • Cada posición visual que deba aparecer/desaparecer necesita su propio material / texture face.
  • La geometría estática debe quedar en una cara separada y fuera de FACES.
  • No presupongas el número final de las faces después del upload: compruébalo dentro de Second Life.
10

Problemas frecuentes

Diagnóstico rápido antes de tocar el script.

No aparece ninguna animación

Comprueba que el mesh está preparado por texture faces, que PART coincide exactamente con el nombre del prim y que FACES utiliza índices que realmente existen.

Una cara PBR no desaparece

El método actual usa alpha Blinn-Phong. Las caras con material PBR no muestran el cambio de visibilidad mediante este mecanismo.

El script dice que PART no existe

PART distingue el nombre exacto del prim. Revisa espacios, puntos, mayúsculas y el nombre real mostrado en el escaneo inicial.

La configuración tarda mucho

Las notecards se leen línea por línea. Con cientos de líneas puede tardar perceptiblemente. Espera hasta ver el mensaje de EOF/configuración válida.

Configuration rejected por memoria

Reduce el número total de PART o FACES. El límite de 64 PART es lógico, pero la memoria Mono disponible sigue siendo finita.

Una cara antigua se queda invisible tras cambiar FACES

Restaura manualmente su alpha o prueba con una copia limpia. Una cara retirada de FACES deja de ser controlada deliberadamente.

Referencia rápida

El bloque completo de una PART.

PART=Exact prim name
MODE=PENDULUM | LINEAR | RANDOM
FACES=0,1,2,3,4
START=0
DELAYS=400,300,200,300,400
REPEAT=2
REPEAT_DELAY=300
CampoRegla
PARTNombre exacto y único del prim enlazado.
MODEPENDULUM, LINEAR o RANDOM.
FACES2..8 índices de caras animadas.
STARTDebe pertenecer a FACES.
DELAYSUn valor por FACE, 100..60000 ms.
REPEATOpcional: vacío, 1..1000000 o INFINITE.
REPEAT_DELAYOpcional: 0..86400000 ms; ignorado si REPEAT está desactivado.
