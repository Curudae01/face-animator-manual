Face Animator

Ein konfigurierbares System zur Animation der Sichtbarkeit einzelner Flächen auf Standard-Prims, verlinkten Objekten und Mesh.

FunktionsweiseKurzreferenz
Standard-PrimsMeshPENDULUM · LINEAR · RANDOMBis zu 64 PARTs

Zwei Einsatzarten

  • Standard-Prims: vorhandene Flächen direkt animieren.
  • Mesh: vorhandene Texture Faces direkt animieren.
  • Erweitertes Mesh: jede Face kann einen anderen vorbereiteten Geometriezustand darstellen.
  • Face Animator verformt keine Geometrie; er steuert Sichtbarkeit.
01

Welche Objekte können animiert werden?

Face Animator arbeitet mit den nummerierten Flächen von Second-Life-Prims.

Nicht auf Mesh beschränkt.

Standard-Prims können ihre normalen vorhandenen Flächen direkt als Animationszustände verwenden. Dies wurde in Second Life mit drei verlinkten Standard-Box-Prims bestätigt.

Direkte Nutzung

  • Boxen, Zylinder, Prismen und andere Standard-Prims.
  • Mehrere verlinkte Standard-Prims.
  • Mesh mit vorhandenen Texture Faces als Animationszustände.
  • Gemischte Linksets aus Standard-Prims und Mesh.

Speziell vorbereitetes Mesh

Nur nötig, wenn unterschiedliche vorbereitete Geometrieformen als Frames dienen sollen. Jede Form benötigt ein eigenes Material / Texture Face.

Was es nicht tut

Face Animator bewegt keine Vertices und verformt keine Objekte. Er zeigt und verbirgt die konfigurierten FACES.

Die aktuelle Version steuert Legacy-/Blinn-Phong-Alpha. Flächen mit PBR-Materialien werden von dieser Sichtbarkeitsmethode nicht unterstützt.

02

Installation

Script und Notecard zusammen aufbewahren.

  1. Kompatibles Objekt rezzen oder bearbeiten.
  2. Den Prim öffnen, in dem Face Animator installiert wird. Empfohlen ist der Root-Prim.
  3. Das mitgelieferte Script und die Notecard mit dem exakten Namen Config Face Animator in dasselbe Prim-Inventar legen.
  4. Notecard mit den tatsächlichen Namen der verlinkten Prims bearbeiten.
  5. Speichern und warten, bis das Laden abgeschlossen ist.
  6. Im Besitzer-Chat prüfen, ob die Konfiguration akzeptiert wurde.
Dasselbe Prim-Inventar

Config Face Animator muss sich im Inventar desselben Prims wie das Script befinden.

03

Config Face Animator

Blockweise Konfiguration, PART für PART.

Zeilen mit # sind Kommentare, leere Zeilen werden ignoriert.

PART=COINS
MODE=PENDULUM
FACES=0,1,2,3,4
START=0
DELAYS=400,300,200,300,400
REPEAT=2
REPEAT_DELAY=300

Für einen weiteren animierten Prim einen neuen Block mit PART=... beginnen.

Große Notecards

Das Script liest bis EOF. Der reale Stresstest las 510 Zeilen und speicherte 64 PARTs korrekt. Große Konfigurationen brauchen merklich länger.

04

MODE

Bewegungsmuster für jede PART.

PENDULUM

MODE=PENDULUM

Bis zum Ende und wieder zurück.

0 → 1 → 2 → 3 → 4 → 3 → 2 → 1 → 0

LINEAR

MODE=LINEAR

Bis zum letzten Zustand, dann direkt zum ersten.

0 → 1 → 2 → 3 → 4 → 0

RANDOM

MODE=RANDOM

Zufällige Sprünge zwischen den konfigurierten FACES ohne sofortige Wiederholung.

05

FACES und START

Legt die Animationsflächen fest.

FACES=0,1,2,3,4
START=2
  • FACES akzeptiert 2 bis 8 Indizes.
  • Sie müssen nicht fortlaufend sein.
  • START muss in FACES enthalten sein.
  • Flächen außerhalb von FACES werden absichtlich nicht verändert.
Bei Änderungen

Wurde eine Fläche durch eine frühere Konfiguration ausgeblendet und später aus FACES entfernt, Alpha manuell wiederherstellen oder mit einer sauberen Kopie testen.

06

DELAYS

Sichtbare Dauer jedes Zustands in Millisekunden.

FACES=0,1,2,3,4
DELAYS=400,300,200,300,400

Jeder Wert gehört zur FACE an derselben Position. Bereich: 100..60000 ms. FACES und DELAYS müssen gleich viele Werte enthalten.

07

REPEAT und REPEAT_DELAY

Optionale Steuerung vollständiger Zyklen pro PART.

EinstellungErgebnis
REPEAT fehltTraditionelle Daueranimation.
REPEAT=Daueranimation; REPEAT_DELAY wird ignoriert.
REPEAT=2Zwei vollständige Zyklen, dann Stopp auf START.
REPEAT=INFINITEUnendlich viele kontrollierte Zyklen.
REPEAT=3
REPEAT_DELAY=2000

REPEAT_DELAY gilt nur bei aktivem REPEAT. Fehlend, leer oder 0 verwendet den normalen START-DELAYS-Wert zwischen Zyklen. REPEAT: 1..1000000. REPEAT_DELAY: 0..86400000 ms.

08

Mehrere PARTs und Kapazität

Jeder verlinkte Prim kann eigene Einstellungen haben.

PART=SKIRT_LEFT
MODE=LINEAR
FACES=0,1,2,3,4
START=0
DELAYS=200,150,100,150,200

PART=SKIRT_RIGHT
MODE=RANDOM
FACES=0,1,2,3,4
START=2
DELAYS=400,300,200,300,400
64maximale logische PARTs
8maximale FACES pro PART
Getestete Kapazität

v1.6.2 wurde mit 64 PARTs × 5 FACES = 320 Frames getestet. 64 × 8 = 512 Frames wurde nicht getestet und wird nicht garantiert. Die reale Kapazität hängt auch vom verfügbaren Speicher ab.

09

Standard-Prims und erweitertes Mesh

Dieselbe Engine unterstützt einfache Flächeneffekte und scheinbare Geometrieanimation.

Standard-Prims

Keine Blender-Vorbereitung nötig. Die vorhandenen nummerierten Flächen direkt in FACES verwenden.

Normales Mesh

Vorhandene Texture Faces können direkt genutzt werden, wenn sie die gewünschten Animationszustände darstellen.

Mesh mit Geometriezuständen

Soll jede Face eine andere Form darstellen, muss das Mesh vorher entsprechend vorbereitet werden:

Geometriezustand
→ Mesh-Material
→ Second-Life-Texture-Face
→ Nummer in FACES

Face Animator erzeugt diese Formen nicht. Er wechselt nur ihre Sichtbarkeit.

10

Fehlerbehebung

Schnelle Prüfungen vor Script-Änderungen.

Nichts animiert

Mesh-Aufbau, exakten PART-Namen und gültige FACES prüfen.

PBR-Fläche verschwindet nicht

Die aktuelle Methode verwendet Blinn-Phong-Alpha; PBR-Flächen reagieren darauf nicht sichtbar.

PART existiert nicht

Den exakten Namen aus dem Startscan verwenden.

Konfiguration lädt lange

Notecards werden zeilenweise gelesen. Auf EOF/valid configuration warten.

Speicherfehler

Gesamtzahl von PARTs oder FACES reduzieren.

11

Kurzreferenz

Vollständiger PART-Block.

PART=Exact prim name
MODE=PENDULUM | LINEAR | RANDOM
FACES=0,1,2,3,4
START=0
DELAYS=400,300,200,300,400
REPEAT=2
REPEAT_DELAY=300
FeldRegel
PARTExakter eindeutiger Prim-Name.
MODEPENDULUM, LINEAR oder RANDOM.
FACES2..8 animierte Indizes.
STARTMuss in FACES stehen.
DELAYSEin Wert pro FACE, 100..60000 ms.
REPEATOptional: leer, 1..1000000 oder INFINITE.
REPEAT_DELAYOptional: 0..86400000 ms; bei deaktiviertem REPEAT ignoriert.
