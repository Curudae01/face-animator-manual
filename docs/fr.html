Face Animator

Animation visuelle pour meshes préparés avec plusieurs états géométriques répartis entre différentes texture faces.

Vérifier la compatibilitéRéférence rapide
PENDULUMLINEARRANDOMJusqu’à 64 PART

Avant de commencer

  • Le mesh doit être spécialement préparé pour ce système.
  • Chaque état visuel doit utiliser une texture face différente.
  • Maximum 8 texture faces par mesh prim.
  • Les faces PBR ne sont pas prises en charge par la méthode actuelle de visibilité.
01

Mon mesh est-il compatible ?

Vérifiez ceci avant d’installer le script.

Face Animator n’anime pas n’importe quel mesh.

L’objet doit déjà contenir plusieurs états géométriques dans le même mesh prim, attribués à des matériaux / texture faces séparés.

Compatible

  • Vêtements, accessoires ou effets créés avec des états séparés.
  • 2 à 8 FACES configurées par PART.
  • Faces legacy / Blinn-Phong pour la visibilité alpha.
  • Prims liés avec des noms uniques.

Non compatible

  • Mesh normal à géométrie unique que le script devrait déformer.
  • Animation par os, rigging ou keyframes Blender.
  • Faces PBR devant disparaître via ce système.
  • Deux prims configurés avec le même nom.

Second Life prend en charge jusqu’à 8 texture faces par mesh prim. Cette limite s’applique à chaque prim, pas à l’ensemble du linkset.

02

Installation

Conservez le script et la notecard ensemble.

  1. Rezzez ou éditez l’objet compatible.
  2. Ouvrez le prim où Face Animator sera installé. Le root prim est recommandé.
  3. Placez dans ce même inventaire le script fourni et la notecard nommée exactement Config Face Animator.
  4. Modifiez la notecard avec les vrais noms des prims liés.
  5. Enregistrez et attendez la fin du chargement.
  6. Vérifiez dans le chat du propriétaire que la configuration est valide.
Même prim

Config Face Animator doit être dans l’inventaire du même prim que le script.

03

Config Face Animator

Configuration par blocs, une PART après l’autre.

Les lignes commençant par # sont des commentaires ; les lignes vides sont ignorées.

PART=COINS
MODE=PENDULUM
FACES=0,1,2,3,4
START=0
DELAYS=400,300,200,300,400
REPEAT=2
REPEAT_DELAY=300

Pour ajouter un autre prim animé, commencez un nouveau bloc avec PART=....

Grandes notecards

Le script lit toute la notecard jusqu’à EOF. Le test réel a lu 510 lignes et stocké 64 PART correctement. Les grandes configurations peuvent prendre plus de temps à charger.

04

MODE

Choisissez comment chaque PART parcourt ses états.

PENDULUM

MODE=PENDULUM

Avance jusqu’à une extrémité puis repart en sens inverse.

0 → 1 → 2 → 3 → 4 → 3 → 2 → 1 → 0

LINEAR

MODE=LINEAR

Avance jusqu’au dernier état puis revient directement au premier.

0 → 1 → 2 → 3 → 4 → 0

RANDOM

MODE=RANDOM

Saute aléatoirement entre les FACES configurées sans répéter immédiatement la face actuelle.

05

FACES et START

Définissez exactement les faces de l’animation.

FACES=0,1,2,3,4
START=2
  • FACES accepte 2 à 8 indices.
  • Ils n’ont pas besoin d’être consécutifs.
  • START doit être présent dans FACES.
  • Une face absente de FACES n’est pas modifiée intentionnellement.
Lors d’une modification

Si une face a été masquée par une ancienne configuration puis retirée de FACES, restaurez son alpha manuellement ou utilisez une copie propre.

06

DELAYS

Durée visible de chaque état, en millisecondes.

FACES=0,1,2,3,4
DELAYS=400,300,200,300,400

Chaque valeur correspond à la FACE située à la même position. Plage : 100..60000 ms. FACES et DELAYS doivent contenir exactement le même nombre de valeurs.

07

REPEAT et REPEAT_DELAY

Contrôle optionnel des cycles complets par PART.

ConfigurationRésultat
REPEAT absentAnimation continue traditionnelle.
REPEAT=Animation continue ; REPEAT_DELAY est ignoré.
REPEAT=2Deux cycles complets puis arrêt sur START.
REPEAT=INFINITECycles complets contrôlés à l’infini.
REPEAT=3
REPEAT_DELAY=2000

REPEAT_DELAY ne s’applique que si REPEAT est actif. S’il est absent, vide ou à 0, le DELAYS normal de START est utilisé entre les cycles. REPEAT : 1..1000000. REPEAT_DELAY : 0..86400000 ms.

08

Plusieurs PART et capacité

Chaque prim lié peut avoir son propre mode, START et ses propres timings.

PART=SKIRT_LEFT
MODE=LINEAR
FACES=0,1,2,3,4
START=0
DELAYS=200,150,100,150,200

PART=SKIRT_RIGHT
MODE=RANDOM
FACES=0,1,2,3,4
START=2
DELAYS=400,300,200,300,400
64PART logiques maximum
8FACES maximum par PART
Capacité vérifiée

v1.6.2 a été testé avec 64 PART × 5 FACES = 320 frames. La combinaison 64 × 8 = 512 frames n’a pas été testée et n’est pas garantie. La capacité réelle dépend aussi de la mémoire disponible.

09

Préparer le mesh

La géométrie animée est créée avant l’arrivée dans Second Life.

état géométrique
→ matériau du mesh
→ texture face Second Life
→ numéro utilisé dans FACES
  • Chaque position visuelle doit avoir son propre matériau / texture face.
  • La géométrie statique doit rester sur une face séparée, hors de FACES.
  • Vérifiez les numéros réels des faces après l’upload.
10

Dépannage

Vérifications rapides avant de modifier le script.

Rien ne s’anime

Vérifiez la préparation du mesh, le nom exact de PART et les indices FACES existants.

Une face PBR ne disparaît pas

La méthode actuelle utilise l’alpha Blinn-Phong ; les faces PBR ne réagissent pas visuellement à ce mécanisme.

PART n’existe pas

Utilisez exactement le nom affiché par le scan au démarrage.

Le chargement est long

Les notecards sont lues ligne par ligne. Attendez le message EOF/configuration valide.

Configuration rejetée pour mémoire

Réduisez le nombre total de PART ou de FACES.

11

Référence rapide

Bloc complet d’une PART.

PART=Exact prim name
MODE=PENDULUM | LINEAR | RANDOM
FACES=0,1,2,3,4
START=0
DELAYS=400,300,200,300,400
REPEAT=2
REPEAT_DELAY=300
ChampRègle
PARTNom exact et unique du prim lié.
MODEPENDULUM, LINEAR ou RANDOM.
FACES2..8 indices animés.
STARTDoit être présent dans FACES.
DELAYSUne valeur par FACE, 100..60000 ms.
REPEATOptionnel : vide, 1..1000000 ou INFINITE.
REPEAT_DELAYOptionnel : 0..86400000 ms ; ignoré si REPEAT est désactivé.

Aucun résultat
