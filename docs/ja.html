Face Animator

標準 prim、リンクオブジェクト、mesh の個別 face の表示を切り替えてアニメーションさせる設定可能なシステムです。

仕組みクイックリファレンス
標準 primMeshPENDULUM · LINEAR · RANDOM最大 64 PART

2つの使い方

  • 標準 prim: 既存の face をそのままアニメーション。
  • Mesh: 既存の texture face をそのままアニメーション。
  • 高度な mesh: 各 face を異なる事前作成 geometry state として使用。
  • Face Animator は geometry を変形せず、表示状態を制御します。
01

どのオブジェクトをアニメーションできますか？

Face Animator は Second Life prim の番号付き face を使用します。

Mesh 専用ではありません。

標準 prim は既存の通常 face をそのまま animation state として使用できます。Second Life 内で3つの標準 box prim をリンクしたオブジェクトで動作確認済みです。

そのまま使用可能

  • Box、Cylinder、Prism などの標準 prim。
  • 複数のリンクされた標準 prim。
  • 既存 texture face を状態として使う mesh。
  • 標準 prim と mesh の混合 linkset。

特別に準備した mesh

異なる事前作成 geometry shape を frame として使う場合のみ必要です。各 shape を別の material / texture face に割り当てます。

できないこと

Face Animator は vertex を移動したり object を変形したりしません。設定された FACES の表示/非表示を切り替えます。

現在のバージョンは legacy / Blinn-Phong alpha を制御します。PBR material face はこの表示方式ではサポートされません。

02

インストール

スクリプトと notecard は同じ prim に入れます。

  1. 対応するオブジェクトを rez または編集します。
  2. Face Animator を入れる prim を開きます。root prim を推奨します。
  3. 付属スクリプトと、正確に Config Face Animator という名前の notecard を同じ prim inventory に入れます。
  4. リンク prim の実際の名前を使って notecard を編集します。
  5. 保存し、読み込み完了まで待ちます。
  6. Owner chat で configuration valid を確認します。
同じ prim

Config Face Animator はスクリプトと同じ prim inventory に存在する必要があります。

03

Config Face Animator

PART ごとのブロック形式で設定します。

# で始まる行はコメント、空行は無視されます。

PART=COINS
MODE=PENDULUM
FACES=0,1,2,3,4
START=0
DELAYS=400,300,200,300,400
REPEAT=2
REPEAT_DELAY=300

別の animating prim を追加する場合は、新しい PART=... 行からブロックを開始します。

長い notecard

スクリプトは EOF まで notecard 全体を読みます。実際の stress test では 510 行を読み、64 PART を正常に保存しました。大きな設定は読み込みに時間がかかります。

04

MODE

各 PART の状態遷移方法を選びます。

PENDULUM

MODE=PENDULUM

端まで進み、逆方向へ戻ります。

0 → 1 → 2 → 3 → 4 → 3 → 2 → 1 → 0

LINEAR

MODE=LINEAR

最後まで進んだ後、最初へ直接戻ります。

0 → 1 → 2 → 3 → 4 → 0

RANDOM

MODE=RANDOM

設定された FACES の中からランダムに移動し、現在の face を直ちに繰り返しません。

05

FACES と START

アニメーションに使用する face を正確に指定します。

FACES=0,1,2,3,4
START=2
  • FACES は 2～8 個の index。
  • 連続番号でなくても構いません。
  • START は FACES に含まれている必要があります。
  • FACES にない face は意図的に変更されません。
既存設定を変更する場合

以前の設定で非表示になった face を FACES から外す場合は、alpha を手動で戻すか、クリーンなコピーで確認してください。

06

DELAYS

各状態を表示する時間をミリ秒で指定します。

FACES=0,1,2,3,4
DELAYS=400,300,200,300,400

各値は同じ位置の FACE に対応します。範囲は 100..60000 ms。FACES と DELAYS の個数は一致する必要があります。

07

REPEAT と REPEAT_DELAY

PART ごとの完全サイクルを任意で制御します。

設定結果
REPEAT なし従来の連続アニメーション。
REPEAT=連続アニメーション。REPEAT_DELAY は無視。
REPEAT=22 サイクル後、START で停止。
REPEAT=INFINITE完全サイクルを無限に繰り返す。
REPEAT=3
REPEAT_DELAY=2000

REPEAT_DELAY は REPEAT が有効な場合のみ使用されます。未指定、空、0 の場合はサイクル間に START の通常 DELAYS を使用します。REPEAT: 1..1000000。REPEAT_DELAY: 0..86400000 ms。

08

複数 PART と容量

各リンク prim は独自の MODE、START、タイミングを設定できます。

PART=SKIRT_LEFT
MODE=LINEAR
FACES=0,1,2,3,4
START=0
DELAYS=200,150,100,150,200

PART=SKIRT_RIGHT
MODE=RANDOM
FACES=0,1,2,3,4
START=2
DELAYS=400,300,200,300,400
64論理 PART 上限
81 PART の FACES 上限
実証済み容量

v1.6.2 は 64 PART × 5 FACES = 320 frames で Second Life 上のテストに成功しています。64 × 8 = 512 frames は未テストで保証されません。実際の容量は利用可能な script memory にも依存します。

09

標準 prim と高度な mesh

同じエンジンで単純な face effect と見かけ上の geometry animation の両方を扱えます。

標準 prim

Blender の準備は不要です。既存の番号付き face を FACES に直接指定します。

通常の mesh

既存 texture face が切り替えたい状態なら、そのまま使用できます。

Geometry state を持つ mesh

各 face に異なる形状を持たせる場合は、mesh を事前に準備します:

geometry state
→ mesh material
→ Second Life texture face
→ FACES で使う番号

Face Animator は形状を生成しません。表示状態だけを切り替えます。

10

トラブルシューティング

スクリプトを変更する前の確認。

何も動かない

Mesh が texture face 方式で準備されているか、PART 名が正確か、FACES index が存在するか確認します。

PBR face が消えない

現在の方式は Blinn-Phong alpha を使用します。PBR face には視覚的な効果がありません。

PART が存在しないと言われる

起動時 scan に表示された正確な prim 名を使用してください。

読み込みに時間がかかる

Notecard は 1 行ずつ読みます。EOF / configuration valid のメッセージまで待ってください。

メモリで設定が拒否される

PART または FACES の総数を減らしてください。
